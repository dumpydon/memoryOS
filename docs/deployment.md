# Free-tier deployment

MemoryOS has one deployable Python service and one frontend. The recommended portfolio setup is:

- **Vercel Hobby** for `apps/web`.
- **Render Free Web Service** for the Dockerized FastAPI/MCP service.
- **Neon** for PostgreSQL with the pgvector extension.

No queues, disks, workers, or managed Render database are required for this scope. Render free services sleep after inactivity, so the first request can wait for a cold start.

## Neon database

Use a Neon database owner with permission to create the `vector` extension. Set `DATABASE_URL` to its TLS PostgreSQL connection string. Ordinary `postgresql://` and `postgres://` URLs are normalized to the installed Psycopg driver without changing encoded credentials or SSL options; `postgresql+psycopg://` also works.

```text
postgresql+psycopg://USER:PASSWORD@HOST/DBNAME?sslmode=require
```

Use the **direct/unpooled** connection for migrations and initial seed. The API can use Neon's pooled TLS connection afterward. Export `DATABASE_URL` through your shell's secret environment (avoid placing real credentials in command history), then run from a trusted machine:

```bash
cd apps/api
uv sync --frozen --no-dev
uv run --no-sync alembic upgrade head
uv run --no-sync memoryos-seed
```

The migration creates `vector` and advances a fresh database to `0002_phase2_engine`. The seed is idempotent, creates the fixed demo and live scopes, and inserts only missing fixture rows. Neither migration nor seed runs automatically at API startup. Run migrations before every release that changes the schema; the seed is only needed to initialize/update authored fixtures.

## Render

The root `render.yaml` defines one free Docker web service rooted at `apps/api`. Connect the GitHub repository to Render and apply the Blueprint. The service listens on `0.0.0.0` and Render’s `PORT`; TLS terminates at Render’s edge. Health checks use `/health/ready`.

| Setting | Configuration |
|---|---|
| Runtime / Root Directory | Docker / `apps/api` |
| Dockerfile / build context | `./Dockerfile` / `.` (relative to Root Directory) |
| Python / dependency installation | `python:3.12-slim`; pinned uv `0.12.10`; `uv sync --frozen --no-dev` |
| Start | Dockerfile CMD: `uvicorn memoryos.main:app --host 0.0.0.0 --port ${PORT:-8000}` through `sh` |
| Health check | `/health/ready` checks database connectivity and migration head; `/health/live` checks the process |

Leave Docker Command unset to use the Dockerfile CMD. Docker services have no separate build-command field. Free Render services do not support a pre-deploy command, so run migrations separately before releasing a schema change. No local PostgreSQL container, mounted disk, or repository `.env` is needed by the deployed image.

Set these Blueprint values in the Render Dashboard:

| Variable | Value | Secret? |
|---|---|---|
| `APP_ENV` | `production` (already set by Blueprint) | no |
| `DATABASE_URL` | Neon TLS PostgreSQL URL | yes |
| `OWNER_API_TOKEN` | generated by the Blueprint or a rotated owner token | yes |
| `WEB_ORIGIN` | exact Vercel origin, for example `https://memoryos.vercel.app` | no |
| `OPENAI_API_KEY` | leave empty for demo-only mode; add only for live mode | yes |
| `EXECUTION_MODE` | `demo` | no |

The Blueprint supplies `OPENAI_MODEL`, `EMBEDDING_MODEL`, `EMBEDDING_DIMENSIONS`, `DEMO_EMBEDDING_MODEL`, `DEMO_EMBEDDING_DIMENSIONS`, `PROVIDER_TIMEOUT_SECONDS`, and `MAX_INTERACTION_CHARS`. Keep both embedding dimensions at `1536`; the live model must match the seeded live scope. `PORT` is supplied by Render. Production rejects empty/whitespace or development owner tokens; CORS allows the configured `WEB_ORIGIN` only. Local development retains its loopback alias.

Render's automatically supplied `RENDER_EXTERNAL_URL` configures the MCP HTTP Host/Origin allowlist. For a custom API domain or another host, set `API_PUBLIC_ORIGIN` to that exact API origin. DNS-rebinding protection remains enabled; arbitrary hosts and origins are rejected.

Demo requests select deterministic providers even when an OpenAI key exists. Live requests require an owner token, an explicit live request, and configured provider credentials. Missing credentials return a clear unavailable response. No paid provider calls occur merely from browsing the public demo. Never put provider keys or owner tokens in the frontend environment. Render Free is suitable for a portfolio demo, not an always-on production SLA.

## Vercel

Create a Vercel project from the repository with these settings:

| Setting | Configuration |
|---|---|
| Framework / Root Directory | Next.js / `apps/web` |
| Node.js | `22.x` (also declared in package engines) |
| Install | Automatic; enable `ENABLE_EXPERIMENTAL_COREPACK` to use the root `packageManager` pin (`pnpm@11.19.0`) and workspace lockfile |
| Build | `pnpm build` |
| Output Directory | Next.js default; no override |

Set `ENABLE_EXPERIMENTAL_COREPACK=1` in Vercel. Avoid overriding installation with a bare `pnpm install`, which can select a different platform-provided pnpm version. The build command runs from `apps/web`:

```bash
pnpm build
```

Set this build-time environment variable in Vercel:

```text
NEXT_PUBLIC_API_BASE_URL=https://YOUR-RENDER-SERVICE.onrender.com
```

The production build fails early if `NEXT_PUBLIC_API_BASE_URL` is absent. Set it to the backend origin without `/v1` or a trailing slash, and rebuild when it changes. Next.js reads `apps/web/.env.local` locally, not the repository-root `.env`. For a local production build, copy `apps/web/.env.example` to `apps/web/.env.local`; this explicitly selects the local API.

Set `WEB_ORIGIN` on Render to the exact final Vercel origin without a trailing slash. Preview domains need their own explicitly configured backend origin policy; wildcard Vercel origins are not allowed. The owner token stays in browser-session React memory after entry in Settings, is sent as a bearer header, and is cleared on reload. Vercel never stores or embeds it.

Platform behavior: [Render Docker](https://render.com/docs/docker), [Render deploy phases](https://render.com/docs/deploys), [Vercel package managers](https://vercel.com/docs/package-managers), and [Vercel Corepack configuration](https://vercel.com/docs/builds/configure-a-build#corepack).

## Release order

1. Create Neon and verify the TLS connection.
2. Run `alembic upgrade head` once.
3. Run `memoryos-seed` once.
4. Apply the Render Blueprint and confirm `/health/ready`.
5. Configure Vercel with `NEXT_PUBLIC_API_BASE_URL` and deploy the web app.
6. Open the dashboard, run the public demo walkthrough, and test one owner-only preview/commit flow.

The repository does not claim a completed cloud deployment. Live provider calls and free-tier cold-start behavior still require verification in the target accounts.
